# Implementation Plan: Centralized Theme Token System

**Branch**: `006-theme-token-system` | **Date**: 2026-05-11 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/006-theme-token-system/spec.md`

## Summary

Consolidate ~90 hardcoded color values (hex + rgba + CSS keywords) scattered across 10 component files into a single `tokens.ts` file. Refactor `muiTheme.ts` to consume tokens and extend the MUI palette with four custom namespaces (gold, surface, border, glow). Replace all hardcoded colors in components with theme palette references (sx props) or direct token imports (SVG attributes, gradient strings, framer-motion configs). Remove duplicate background pattern from App.tsx. Zero visual regression guaranteed.

## Migration Strategy Summary

### Strategy Matrix

| Context | Migration Approach | Example |
|---------|-------------------|---------|
| `sx` prop (theme available) | `theme.palette.gold.main` via callback | `<Box sx={{ color: (t) => t.palette.gold.main }}>` |
| SVG `stroke`/`fill`/`stopColor` | Import from `tokens.ts` | `stroke={colors.gold.main}` |
| Inline `style` object | Import from `tokens.ts` | `style={{ background: colors.gold.main }}` |
| Framer-motion `style` | Import from `tokens.ts` | `style={{ borderColor: colors.border.default }}` |
| Gradient string | Interpolate token constant | `` `linear-gradient(${colors.gold.main}, ${colors.gold.light})` `` |
| SVG inside MUI component | `currentColor` where parent sets color | `stroke="currentColor"` |
| CSS keyword (`"black"`, `"white"`) | Theme palette reference | `color: "common.black"` or `theme.palette.getContrastText(...)` |

### Shade Mismatch Fallback

If MUI's `alpha()` utility produces a non-matching color for a specific opacity, the exact rgba string is stored as a named token constant in `tokens.ts` instead of being constructed at runtime. This ensures pixel-identical rendering.
